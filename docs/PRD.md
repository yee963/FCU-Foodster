# 產品需求文件 (PRD)

## 專案名稱：FCU-Foodster (逢甲專屬揪團平台)
**專案描述**：解決逢甲學生用餐排隊耗時、外送門檻高及揪團收款混亂的痛點，建立一個校園專屬的揪團訂餐平台。

---

## 1. 專案概述

### 背景與動機
逢甲大學周邊美食眾多，但學生在用餐高峰期常面臨三大痛點：
1. **排隊耗時**：買飯動輒需等待 20 分鐘以上。
2. **外送門檻高**：單人訂購需負擔高額運費或未達起送價。
3. **收款混亂**：傳統用 Line 揪團，團長在統計金額與代墊款項時極易出錯。

本專題旨在建立一個校園專屬的揪團平台，解決上述真實存在的社交與生活問題。

### 目標用戶
- 逢甲大學在校學生
- 尋求省時、想與同學分攤外送運費的族群
- 經常擔任「團長」幫大家訂餐的學生

### 核心價值主張
- **省時便利**：減少現場排隊時間，透過揪團快速成單。
- **降低門檻**：共享外送運費，輕鬆達到店家起送標準。
- **財務清晰**：系統化計算每人應付金額，減少團長代墊風險與算錯錢的困擾。

---

## 2. 功能需求

### 2.1 註冊與登入
- **使用者故事**：作為一名學生，我希望能夠註冊並登入平台，以便安全地發起或參與揪團。
- **說明**：支援基本帳號密碼註冊，未來可擴充學生信箱驗證機制。

### 2.2 發起揪團 (團長功能)
- **使用者故事**：作為一名團長，我希望能夠快速建立一個揪團訂單（包含選擇店家、結單時間、取餐地點與收款帳號），以便邀請同學一起訂餐。
- **說明**：團長設定好條件後，系統會生成專屬揪團連結或進入揪團大廳供大家點選。

### 2.3 參與揪團 (團員功能)
- **使用者故事**：作為一名團員，我希望能夠在揪團截止前瀏覽菜單並加入想吃的餐點，以便跟團訂餐。
- **說明**：清楚顯示店家菜單、價格，並即時更新目前揪團的總金額與人數。

### 2.4 訂單統計與分帳管理
- **使用者故事**：作為一名團長，我希望系統能自動統計所有人的餐點明細與應付總額（含平分後的運費），以便快速下單與對帳。
- **說明**：提供一目了然的總表，並顯示各團員的付款狀態（已付款/未付款）。

### 2.5 訂單狀態與通知
- **使用者故事**：作為一名使用者，我希望能夠查看訂單的當前狀態（如：揪團中、已下單、待取餐、已完成），以便掌握餐點進度。
- **說明**：狀態由團長更新，團員可即時於平台上查看。

---

## 3. 非功能需求

### 3.1 技術限制
- **後端框架**：使用 Python Flask。
- **前端渲染**：使用 Jinja2 模板引擎與原生 HTML/CSS/JS。
- **資料庫**：使用 SQLite，適合輕量級校園應用。

### 3.2 效能與安全考量
- 密碼需進行雜湊（Hash）加密儲存（例如使用 bcrypt 或 Werkzeug 的 security 模組）。
- 防止 SQL Injection 與 XSS 攻擊。
- 系統需能承受用餐尖峰時段的並行存取。

---

## 4. MVP 範圍 (Minimum Viable Product)

### Must Have (必須具備 - 第一階段目標)
- 使用者註冊與登入系統。
- 團長發起揪團與設定基本資訊（店家、時間、地點）。
- 團員瀏覽揪團清單並加入餐點。
- 系統自動彙整訂單明細與計算每人應付總額（餐費 + 均分運費）。

### Should Have (應該具備 - 第二階段目標)
- 團長可標記團員的「付款狀態」。
- 揪團訂單狀態追蹤（揪團中、結單、已抵達）。
- 搜尋與過濾當前進行中的揪團。

### Nice to Have (有了更好 - 未來擴充功能)
- 整合 Line Notify 機器人發送結單或取餐通知。
- 上傳收款 QR Code（如 Line Pay / 銀行轉帳）。
- 店家菜單資料庫與圖片上傳。
